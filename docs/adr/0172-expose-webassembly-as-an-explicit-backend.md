# Expose WebAssembly as an explicit backend

SheetOM will publish the first-class WebAssembly Browser Backend as a separate, lockstep-versioned, ESM-only public `@sheetom/wasm` package so native consumers never install its bytes. A private transport-neutral Engine Binding lets the native and WebAssembly adapters reuse one JavaScript CSSOM Facade rather than duplicate public state semantics. Its `createSheetOM()` factory shares one concurrent default initialization and returns the same frozen facade per JavaScript realm, while an explicit `URL`, `Response`, `ArrayBuffer` or `WebAssembly.Module` creates an independent backend-bound facade. Classes from independent facades have distinct identity. The external single-threaded `wasm32-unknown-unknown` module is built on pinned stable Rust through an exact-version `wasm-bindgen` adapter, resolved relative to `import.meta.url`, supports streaming instantiation with an ArrayBuffer fallback, and is never embedded in JavaScript. Stable Rust uses aborting WASM panics: the adapter converts an unexpected trap to a stable binding error, permanently poisons and evicts that default instance without retrying it, and requires the caller to initialize a new facade; expected failures remain transactional Rust results. Rust handles are released internally through garbage-collection finalization without adding a public disposal API or making correctness depend on finalizer timing. WASM retains the native default Resource Budget and must execute the same applicable compatibility, process-safety and reparsing contracts; it does not require WASI or cross-origin isolation and is not an automatic fallback for a missing native package. One Compatibility Report records both backend dimensions, and publication is blocked by direct-HTTP and Vite, esbuild, Rollup and Webpack consumer tests in pinned Chromium, Firefox and WebKit on the main thread and in a dedicated worker, plus memory-soak and an absolute browser Publisher workload calibrated from the first implementation. It claims only measured modern-browser evidence until historical version tests establish minimums; other isolates graduate only through exact runtime evidence. Exact-version `wasm-bindgen` and Binaryen tooling remains external and reproducibly pinned unless a required local patch justifies a separately provenanced source import; a pinned deterministic `wasm-opt -Oz` pass is retained only if its bytes pass the complete matrix.
